# mine_plugin — Maple Blocks (Клён)

Плагин для Paper 1.21.1 + ресурспак, добавляющие два «чистых» кастомных блока:

| Блок | Предмет | Ванильный BlockState | CustomModelData |
|---|---|---|---|
| **Клён** (Maple Log) | `note_block` | `note_block[instrument=didgeridoo,note=1]` | `1001` |
| **Обтёсанный клён** | `note_block` | `note_block[instrument=didgeridoo,note=2]` | `1003` |
| **Кленовая древесина** | `note_block` | `note_block[instrument=didgeridoo,note=3]` | `1005` |
| **Обтёсанная кленовая древесина** | `note_block` | `note_block[instrument=didgeridoo,note=4]` | `1006` |
| **Кленовые доски** | `note_block` | `note_block[instrument=didgeridoo,note=5]` | `1004` |
| **Листва клёна** (Maple Leaves) | `azalea_leaves` | `azalea_leaves[distance=7,persistent=true,waterlogged=false]` | `1002` |
| **Кленовая дверь** | `warped_door` | `warped_door[powered=true]` (32 состояния ориентации) | `1007` |
| **Кленовый люк** | `warped_trapdoor` | `warped_trapdoor[powered=true,waterlogged=false]` | `1008` |

## Крафты и механики дерева (v1.8.0)

**Кастомные результаты** (настоящие кленовые блоки):
- 1 бревно / обтёсанное бревно / древесина / обтёсанная древесина → **4 кленовые доски**
- 4 бревна (2×2) → **3 кленовые древесины**; 4 обтёсанных бревна → 3 обтёсанные древесины
- **Обтёсывание топором**: ПКМ топором по Клёну/Древесине → обтёсанный вариант (звук, расход прочности — как в ванилле)

**Кленовые двери и люки — кастомные (v1.9.0)**: у дверей/люков свойство `powered` меняется только сервером (редстоуном). Плагин блокирует физику всех варповых дверей/люков, поэтому ветка `powered=true` недостижима в выживании и зарезервирована под клён. Открывание/закрывание, звуки и коллизия — полностью ванильные (клиентское предсказание сохраняет `powered`, текстура не мерцает). Цена: варповые и кленовые двери/люки на сервере **не реагируют на редстоун** (открытие рукой работает).

**Ванильные результаты из кленовых досок** (у остальных фигурных блоков нет серверного свойства, которое можно зарезервировать, — их геометрия и коллизия зашиты в движке, поэтому рецепты выдают еловые аналоги; заменить семейство можно в MapleRecipes):
- 6 досок → **4 ступени**, 3 доски → **6 плит**
- 4 доски + 2 палки → **3 забора**, 2 доски + 4 палки → **калитка**
- 6 досок → **3 кленовые двери** (кастомные, с вашими текстурами!), 6 досок → **2 кленовых люка** (кастомные!)
- 1 доска → **кнопка**, 2 доски → **нажимная плита**
- 5 досок → **лодка**, 6 досок + 2 плиты → **бочка**, 3 доски → **4 миски**
- 2 доски → **4 палки**, 4 доски → **верстак**, 8 досок → **сундук**

Кастомные ингредиенты матчатся через `ExactChoice` — обычные нотные блоки в кленовых крафтах не работают, и наоборот.

Не включено намеренно: таблички, подвесные таблички, полки (по требованиям проекта). Саженец требует кастомного роста дерева — текстура `clen_sapling` сохранена в паке на будущее.

## Почему не oak_log / oak_leaves

Метод «занятых BlockState» работает только с блоками, у которых есть **недостижимые** состояния. У `oak_log` всего 3 состояния (`axis=x/y/z`) — все используются игрой. У `oak_leaves` 28 состояний — и все достижимы в выживании (например, `distance=7,persistent=false` возникает у каждой срубленной кроны за мгновение до распада листвы). Резервировать там нечего: перекраска сломала бы настоящие дубовые блоки по всему миру. Поэтому:

- **Клён** — нотный блок (настоящее дерево: топор, звуки дерева, hardness 0.8). Плагин отменяет физику всех нотных блоков, поэтому ванильный ноутблок навсегда остаётся `harp` и зарезервированное состояние `didgeridoo` недостижимо в выживании.
- **Листва** — **настоящая листва азалии** (azalea_leaves): полный хитбокс, прозрачный (cutout) рендер, родные звуки листвы, висит в воздухе без опоры, правильная скорость разрушения. Почему состояние `distance=7, persistent=true, waterlogged=false` безопасно резервировать:
  - вся природная/выросшая листва имеет `persistent=false` — включая транзитное состояние `distance=7` распадающейся кроны срубленного дерева — совпадения невозможны;
  - игрок, ставящий ванильную листву азалии вдали от брёвен, получил бы `persistent=true, distance=7`, но `distance` **никак не влияет на внешний вид** ванильной листвы, поэтому плагин молча переписывает такие установки на `distance=6` — для игрока ничего не меняется, коллизии нет;
  - заливание наших блоков водой из ведра отменяется плагином (`waterlogged` зафиксирован).

## Фикс стакания (v1.2.0)

Ванильный клиент не ставит блоки на нотный блок без шифта (правый клик = «настроить ноту»). Плагин перехватывает клик по Клёну и выполняет установку блока **на стороне сервера**: вызывается обычный `BlockPlaceEvent` (совместимость с плагинами защиты), расходуется предмет, играет звук. Клён стакается как обычное бревно.

## Модели предметов: два формата

- `assets/minecraft/models/item/*.json` со `overrides` по `custom_model_data` — для клиентов **1.21.1–1.21.3**;
- `assets/minecraft/items/*.json` (новый формат item definitions, `range_dispatch`) — для клиентов **1.21.4+**.

Благодаря этому кастомные текстуры видны в инвентаре независимо от версии клиента.

## Сборка плагина

Требуется JDK 21 и Maven:

```bash
mvn clean package
```

Готовый jar: `target/MapleBlocks-1.9.0.jar` → положить в папку `plugins/` сервера Paper 1.21.1.

## Установка ресурспака

Заархивируйте **содержимое** папки `resourcepack/` (так, чтобы `pack.mcmeta` был в корне zip):

```bash
cd resourcepack && zip -r ../MapleBlocks-ResourcePack.zip . && cd ..
```

Затем либо положите zip в `resourcepacks/` клиента, либо раздавайте с сервера через `resource-pack=` в `server.properties`. После смены пака в игре нажмите **F3+T**.

## Использование

- `/maple give <log|stripped_log|wood|stripped_wood|planks|leaves|door|trapdoor> [кол-во]`
- Право: `mapleblocks.give` (по умолчанию op)

## Игровое поведение

- **Клён**: звуки дерева, топор ломает быстрее, дроп всегда (как у брёвен), стакается и обстраивается без шифта, правый клик не настраивает ноту, редстоун не проигрывает звук.
- **Листва клёна**: настоящая листва — прозрачная текстура, полный хитбокс, родные звуки листвы, висит без опоры и никогда не распадается, ломается с правильной скоростью, дроп **только ножницами**.
- Взрывы: клён дропает себя, листва сгорает без дропа (ванильное поведение).
- Идентификация предметов через PersistentDataContainer (`mapleblocks:maple_block`) — надёжнее, чем только CustomModelData.

## Защита состояний блоков (v1.6.0)

Minecraft на каждом обновлении соседей пересчитывает у нотного блока **инструмент** (от блоков снизу/сверху), а у листвы — **distance**. `BlockPhysicsEvent` Paper гарантированно вызывается только для «корневого» блока обновления — соседи пересчитываются «тихо», без события. Именно поэтому клён превращался в нотный блок, когда рядом ставили или ломали обычные блоки.

Многослойная защита (работает без правки конфигов):
1. отмена `BlockPhysicsEvent` для всех `note_block` и для `azalea_leaves` строго в нашем состоянии — покрывает обновления, адресованные самому блоку;
2. **каждое корневое physics-событие любого блока дополнительно ставит в очередь переустановку кленовых соседей на следующий тик** — покрывает тихие пересчёты соседей (установка/ломание блоков рядом, вода, песок, поршни и т.д.);
3. обработчики установки/разрушения/взрывов защищают окрестность явно (покрывает операции вообще без physics);
4. каноничное состояние принудительно пересылается ближайшим клиентам (клиентское предсказание может показывать устаревшее состояние, которое сервер не рассылал);
5. поршням запрещено двигать кленовые блоки (перемещение пересчитало бы состояние без события);
6. выращиваемые деревья не перезаписывают кленовые блоки;
7. очередь переустановок дедуплицируется за тик — штормы обновлений (потоки воды, большие взрывы) не создают лишней нагрузки.

Для гарантированного отсутствия любого мерцания дополнительно включите в `config/paper-global.yml`:

```yaml
block-updates:
  disable-noteblock-updates: true
```

## Известные ограничения метода

- Ванильные нотные блоки на сервере **всегда звучат как harp** (физика нотных блоков заблокирована, инструмент не меняется от блока снизу). Настройка нот кликом и проигрывание работают. Стандартная цена note_block-метода (так же у ItemsAdder/Oraxen).
- При серверной установке блока против Клёна блоки с ориентацией (ступени, брёвна, печки) ставятся в положении по умолчанию — клиент не передаёт данные прицела при клике по «интерактивному» блоку.
- Pick-block (СКМ в креативе) вернёт ванильный блок-носитель.
- Игрок, поставивший ванильную листву азалии дальше 6 блоков от брёвен, получает `distance=6` вместо `distance=7` — визуально и функционально это неотличимо.
